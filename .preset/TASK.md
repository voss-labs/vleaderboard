# Complete available contribution history

## Goal

Restore missing historical contributions and make each contributor's exact work inspectable. Boss explicitly wants earlier work included, with individual dated records and GitHub links. Collect all available default-branch non-merge commit history and all PR states for every repository in the current public VOSS Labs catalog. Default the board and contributor API to All time; retain the existing optional month and 30-day filters and merged-PR ranking policy.

Task `proj-2a3d9fa34f971f90`; source baseline `cb9514c66a31dc1c4ec337a775d827db3c7ccdac` on `main`/`origin/main`. The prior production transport fix is deployed and working; `.preset/CAPTURE-TASK.md` and `CAPTURE-FIX.md` preserve that work. `.preset/HISTORY-AUDIT.md` documents the old ten-record limitation; its proposed one-page increase is superseded by Boss's clarified full-history requirement.

Parent verified the cause against actual GitHub history: vroom has 24 default-branch commit records, 15 non-merges. Parth's linked GitHub ID is `149477150`; commit `2189670e140eefffa8041e53de47655d8669059f`, committed `2026-10-02T17:54:21Z`, adds 744 and removes 213 lines and is outside the latest ten records. It belongs in both October and All time. His PRs #73 and #64 are open and #63 is closed without merge; zero merged PRs is correct. Do not fabricate merges or change event dates to alter his rank.

Parent measured 17 public repositories, 325 raw commit records and 151 PR records. The largest repository, verp, has 109 commits and 83 PRs; every other commit history has at most 44 records. Full pagination at 100 per page currently needs 35 history/PR pages plus one catalog request: 36 external reads, within the existing 44-read allowance. These are dated observations, not constants or guaranteed future sizes.

## Approach

1. Keep the existing Worker, scheduled capture, public KV and HTTP-reader architecture. Follow every GraphQL history cursor and every REST PR next-page indicator until exhausted. A page size of 100 is transport pagination, never a total-history or display cap. Capture commit SHA, plain message headline, committed date, linked author ID, additions, deletions and public URL; capture PR number, title, state, author, opened, merged and closed timestamps and URL. Keep merge-commit and bot exclusions and linked numeric identity attribution. Do not infer identity from names, email or co-author trailers. Read the current public catalog, including current fork/archive policy; all history means this captured default-branch scope, not every branch, private/deleted repository or the person's entire GitHub lifetime.
2. Make page traversal fail closed. Require valid page shape, at most 100 nodes per page, a nonempty progressing cursor when another page exists, and rejection of cursor cycles, repeated/nonprogressing REST pages, malformed records, contradictory terminal metadata and detectable gaps. Anchor multipage commit traversal to the same captured head or reject a head change; do not silently join changing branch histories. Deduplicate by repository plus SHA/PR identity without disguising inconsistent duplicates or pagination faults as complete history. Missing changed-line measurements remain null and cannot become measured zero. Empty repositories are valid exhausted histories. Any incomplete traversal, malformed required data, upstream/rate error or exhausted budget rejects the entire new publication and retains last good KV byte-for-byte.
3. Preserve the 44-request shared allowance, 45-second capture deadline, eight-second per-request timeout, maximum three external requests in flight and eight-MB stored-document bound. Every additional page uses the existing transport and shared budget. Validation may use an operational maximum derived from those global bounds, but must not reintroduce an arbitrary ten/100-record per-repository history limit. Keep manual redirect rejection and sanitized diagnostics. No D1, migrations, per-contributor upstream requests, broader permissions or new remote resource is needed for the measured volume.
4. Use the agreed backward-compatible record contract: retain snapshot version 1; add optional-on-read `CodeCommit.messageHeadline?: string`, `WorkItem.closedAt?: string | null` and `RepositoryWork.captureComplete?: boolean`. New captures always set those fields, with `captureComplete: true` only after all PR pages exhaust; existing `RepositoryCode.captureComplete` must likewise prove complete traversal. Strict publication additionally requires complete history for every current repository. Strict stored reads continue to accept known legacy shapes and reject unknown fields, bad identities, invalid dates/URLs and inconsistent state/timestamps. A legacy snapshot without explicit full PR coverage remains partial; missing old headlines/closed dates are unavailable, never invented. The data owner may introduce a small shared helper for this completeness test. Tests must establish that old production KV remains readable until the first successful full capture.
5. Derive summaries, individual records, filters and API coverage from the same captured snapshot and capture-time-anchored UTC `[from,to)` semantics. Defaults become `all` in both page state and `/api/leaderboard` when no period is supplied; explicit periods retain their current meaning. A PR opened outside a selected window but merged inside it must still explain its merged count; select records when an applicable event falls inside the window and show those event dates. Listing a PR must not make a closed-unmerged record count as merged. Preserve ranked ties and current sorting by merged PRs; this task does not define a new score. Retain honest zero rows unless independently required for presentation, and never hide real historical work as an ingestion fix.
6. Expand each contributor's repository detail into exact commit and PR records derived from raw `snapshot.code` and `snapshot.work`; `snapshot.activity` is a recent bounded feed and cannot supply the full record list. Show commit headline, linked abbreviated SHA with the full SHA available, committed date and measured +/−; show PR number/title, current state, opened date and applicable merged/closed dates with links. All eligible records remain accessible, with no hidden first-ten/100 truncation. Native expandable groups or client-side Show more are acceptable if every record is reachable. Render upstream titles as plain text. Provide clear empty/unavailable states and keyboard/mobile behavior. Keep selected UTC dates and capture timestamp visible near period/scope controls. All time is the period label; complete available history is claimed only when saved completeness proves it. Old captures remain labeled partial with their recorded limitations.
7. Remove hardcoded latest-ten/first-100 claims from collectors, derived coverage, report metadata, component text and README. The API must distinguish page size from historical record limits; `100` must not remain a machine-readable total cap. Expose explicit PR/code history completeness and accurate scope. Keep HTTP routes KV-only, no-store, production-preview-disabled and free of tokens or operational diagnostics. Summaries and displayed record counts must agree with the same exclusion/date rules.
8. Write focused regressions before relying on the fix. Cover Parth's linked commit beyond record ten and correct +744/−213 totals; more than 100 commit records and more than 100 PRs; merge exclusion; PR opened/merged/closed distinctions; exact date boundaries; identity nulls; advancing cursors and safe empty histories; duplicate/cyclic/malformed pages and detectable pagination gaps; request budget and maximum concurrency; deadline/failure retention; larger strict valid snapshots and legacy reads. Confirm new publication cannot replace the last good document with partial history. UI tests should verify record visibility, selected-window agreement, real links/timestamps, old-record fallback and no total-history display cap. Do not add tests that merely repeat labels without verifying behavior.
9. Run focused tests, then the full suite, generated types/typecheck, production build and Wrangler dry-run. Perform an independent diff/data review, then genuine authenticated collection through the freshly built scheduled handler inside workerd with isolated empty local KV. Verify complete current histories, Parth's record and line totals, both built APIs, and byte-identical retention after a deliberate failed invocation. Node collection or mock success does not prove this runtime path.
10. Parent deploys the authorized history fix to the existing Worker using the original token, KV binding and Cron. Verify a real production scheduled publication, strict remote KV validity, actual request count and history completeness, matching live snapshot/contributor API and rendered All time board with Parth's record. Compare against the live catalog at verification time rather than requiring stale counts. Record version/timestamps, observed scope and any genuine remaining limitation in `.preset/`. Deployment alone or HTTP 200 is insufficient completion evidence.

## Evidence and tradeoff

`.preset/HISTORY-RESEARCH.md` records primary sources and the dated measurements. Weekly contributor-statistics aggregates were considered and rejected: they cannot produce individual SHA/title/date/link details or exact arbitrary date windows, may be asynchronously unavailable, and exclude empty commits. A one-page 100 increase would recover Parth today but would still omit available history in verp; cursor traversal meets the clarified requirement using the current small dataset and existing bounds. If future growth exceeds those bounds, keep the last complete capture and report the safe failure; do not silently label a partial replacement complete.
