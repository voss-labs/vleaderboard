# Unified Cloudflare Worker

## Goal

Prepare the existing VLeaderboard website and contributor API to run in one Cloudflare Worker. The Worker serves React Router 8 SSR, built static assets, `/api/snapshot` and `/api/leaderboard`; a 15-minute scheduled handler captures public GitHub data into one KV snapshot. Public requests read that snapshot and never scan GitHub. Deliver working code, configuration, local validation and deployment instructions. Remote resources, secret upload and public deployment are outside this task.

Preserve the verified leaderboard from commit `210dbaddf56c9ec26e4cd77b7104acb4116166e3`: every discovered public VOSS repository, merged-PR ranking, linked GitHub identities, unknown values as `null`, and honest 100-PR/latest-10-default-branch-record capture limits. Production remains genuine-GitHub-only; fixtures require explicit development opt-in.

## Approach

1. Integrate the verified stable tooling: `@cloudflare/vite-plugin` 1.64.0 supports the current Vite 8 and Wrangler 4.151.1 supports Node 24. Pin compatible packages and lockfile; add the Cloudflare plugin to the `ssr` Vite environment before `reactRouter()`, retaining Tailwind. Add `workers/app.ts`, `wrangler.jsonc`, generated binding types and explicit web-stream `app/entry.server.tsx`. Keep SSR and normal asset-first routing. Use compatibility date `2026-10-17`, required `GITHUB_TOKEN` secret, a KV binding, the 15-minute Cron Trigger, logs and traces; verify all fields against the installed schema. Update scripts, ignored local secret/runtime files, examples, README and the existing Node container instructions so they describe the supported Worker workflow consistently.
2. Inject a snapshot reader through a shared typed React Router `createContext` key and a fresh `RouterContextProvider` per request. Both existing routes use that reader. Remove import-time `process.env` token capture and implicit preview policy from the reusable collector; secrets enter only through Worker bindings. Reject unsupported methods, unknown modes and malformed IDs before KV access; validate catalog membership after reading the document. Preserve `no-store`, current all-repository behavior and HTTP 400 production-preview rejection. Keep SSR usable before priming through an unavailable snapshot; preserve the API snapshot contract unless its client explicitly handles HTTP 503. Refresh reads KV only, with copy explaining the 15-minute capture cadence. Development preview must be explicitly enabled and must never seed the production KV snapshot.
3. Add a small snapshot service with a versioned, validated public JSON envelope containing capture time and `OfficeSnapshot`. HTTP reads handle missing/malformed documents with honest unavailable state and mark old last-good data stale using a documented freshness threshold derived from the schedule. The scheduled handler creates and awaits one invocation-local collector, validates source/schema/relationships before writing, and keeps the previous successful document when GitHub, authentication, validation, request budget or deadline fails. Bounded-history `partial` is valid; missing repository measurements caused by a failed refresh must not replace successful data. No public refresh endpoint, cross-request I/O promises, short KV expiration or module-level persistence assumptions.
4. Replace REST commit-list/per-SHA-detail capture with one authenticated GraphQL default-branch history query per repository, preserving the `CodeResult` contract. Request ten history records, SHA, committed time, additions/deletions, parent count, linked author and pagination. Exclude merges, deduplicate SHA, use only validated linked numeric GitHub identities, retain unattributed authors and unknown stats, and report incomplete pagination truthfully. Do not infer identities from names/emails or request emails. Handle null/empty branches, malformed nodes, HTTP failures, GraphQL errors on HTTP 200 and rate-limit/reset headers. Reuse the shared request limiter, timeout and failure conventions for REST and GraphQL; keep at most three upstream requests active. Remove the obsolete 20/600 REST-detail allowance from Worker capture labels; a nullable `detailReadLimit` with conditional copy is sufficient while preserving rows and unknowns.
5. Bound the entire scheduled scan with an explicit external-request allowance below the current Free limit of 50 and an elapsed-time deadline. REST catalog/PRs plus GraphQL code require about 33 external calls for the current 16 repositories before storage operations. Account for catalog pages and runtime/storage limits, reject redirects, avoid uncontrolled retries, and stop safely as the catalog grows while retaining last-good data and stale coverage. Document the current-size budget and growth limit; do not claim arbitrary organization sizes fit Free. No full-history ingestion, webhooks, D1 or new auth layer.

## Ownership and coordination

Two implementation workers may run in parallel after this plan validates. They share the codebase, must preserve others' edits and coordinate contract changes before touching another owner's files.

| Owner | Files and responsibility |
| --- | --- |
| Platform worker | `workers/app.ts`, Wrangler/Vite/React Router/TypeScript configuration, package files and lockfile, generated binding types, `app/entry.server.tsx`, typed reader context, snapshot KV service/validation, `app/data/load-snapshot.server.ts`, `app/routes/home.tsx`, `app/routes/api.snapshot.ts`, `.gitignore`, environment examples, README/container instructions and platform/context/storage tests. Preserve the current UI except necessary source/capture wording. |
| GitHub data worker | `app/data/github.server.ts`, `app/data/github-code.server.ts`, `app/data/github-failure.server.ts`, any narrowly scoped GraphQL/request helper, and data-source/normalization/budget tests. Own any necessary shared code-coverage type/label adjustment after notifying the platform worker. Preserve derivations, periods, identity semantics and the public snapshot shape. |
| Parent | Submit phase artifacts, integrate/review both workers, run final checks and local servers, inspect browser behavior, record evidence and manage Git/checkpoints. No remote Cloudflare mutations. |

The collector remains `createSnapshotLoader` with explicit token, fetch/time controls and preview policy; the context reader retains the current `{ mode, repositoryId? } -> Promise<OfficeSnapshot>` route-facing contract. The data worker must expose the collection-wide request/deadline options and actual coverage metadata before the platform worker wires scheduled capture. Keep tests for each owner's seam in separate files; coordinate existing test edits rather than overwriting them.

## Validation

- Preserve the existing 40-test domain baseline and adjust obsolete REST-detail fixtures deliberately. Verify latest-ten capture, merge exclusion, SHA deduplication, linked/unlinked authors, measured zero versus unknown, pagination, all-repository aggregation, rate limits, GraphQL error envelopes and the shared concurrency/request/deadline bounds. A 16-repository fixture must demonstrate the expected 33 external calls without per-SHA fetches.
- Test the platform failure boundaries: explicit preview rejection before storage/upstream work; request-local typed context and runtime secret selection; valid/malformed/missing KV; successful scheduled write; failed or incomplete refresh preserving last-good data; stale age; schema/source rejection; and zero GitHub requests from SSR/API readers. Do not log or serialize credentials.
- Run project-local Wrangler type generation, all tests, TypeScript, production build and a local packaging dry run. Verify the generated configuration and Worker dependency graph use web SSR and contain no exposed token or obsolete Node server path. Do not call remote deployment or secret commands.
- Use local scheduled invocation with a mocked upstream for deterministic first capture, failure and persistence checks. Locally smoke-test `/`, `/api/snapshot`, a real hashed asset, 404, unsupported methods, malformed parameters and production preview rejection. Verify desktop/mobile leaderboard rendering, refresh-as-KV-read behavior, search, periods, details, coverage, unknowns and no browser hydration/runtime errors. Record what local tests prove and what still requires eventual deployment credentials/KV resource binding.

## Outcome

One Worker now serves the existing website, static assets and both cached APIs. `workers/app.ts` connects React Router 8 typed request context and the scheduled KV publisher. Runtime secrets are explicit bindings; no import-time process token or public capture endpoint remains. The public report reuses shared ranking and exposes contributor identities, avatars, PR/commit/line metrics, repository breakdowns, nulls and limits. Refresh only reads KV. Validated snapshots survive failed captures, age stale after30minutes and never fall back to production fixtures.

GraphQL history removes per-SHA requests while retaining the approved bounded scope. Transport enforces44 external requests,3active,8-second timeouts and45-second invocation deadline. The real16-repo capture published successfully. Stable Cloudflare tooling, generated types, compatibility config, logs/traces, ignored secret examples, documented first-deploy secret bootstrap and local container instructions are included. Independent review corrections are resolved. No remote resource, credential upload or public deployment was performed.
