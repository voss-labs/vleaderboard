# Browser acceptance checklist

Use the current PRODUCT and ARCHITECTURE contracts as authority. This is a test plan, not a claim of passing checks.

1. Initial desktop render shows a detailed pixel office, two named maintainer rooms, three core tables, exactly four project rooms, commons and separate DevRel. No advisor/faculty rooms.
2. Each side panel independently collapses/reopens. Canvas fills resulting space, preserves a sensible camera center and keeps controls available.
3. All rooms lists the complete snapshot catalog. Search and keyboard navigation work. An off-main repository opens a separate room; Back restores the four-room main floor.
4. Canvas and accessible people controls select the same person. Details show their correct role and known/unknown source data. Follow tracks them; manual camera input exits follow.
5. Ambient work and DevRel presentation are visibly animated. Simulated messages are labeled and attributed. Tour starts a slow corridor visit without altering factual ranking.
6. Pause freezes world movement and resumes without jumps. Reduced motion and hidden-tab behavior avoid catch-up. Selection/camera buttons remain usable while paused.
7. Period changes alter the contribution board correctly for available data. Competition ties, bot exclusion, duplicate IDs and cutoff boundaries pass domain tests.
8. GitHub snapshot mode shows real catalog/work links and freshness/coverage. Errors retain truthful stale/unavailable state, not synthetic replacement. Empty preview work URLs are never linked to invented GitHub PRs.
9. Mobile layout at 390px and narrow320px stays usable: reachable controls, drawers, room directory, map interactions, no page-wide horizontal overflow or unreadable text.
10. Typecheck, production build and meaningful domain/motion tests pass. Browser logs show no application hydration/render errors. Record any unverified external-live behavior explicitly.
